# MaintBot

Telegram-бот для управления серверным сервисом: мониторинг, подписки, поддержка и уведомления в одном месте.
Пользователи получают доступ и персональные ссылки через бота, а сотрудники обрабатывают заявки и следят за серверами из Telegram.

## Что умеет бот

- **Мониторинг серверов.** Состояние локальных и удалённых серверов, загрузка памяти и диска, uptime, DNS, TLS-сертификаты, UFW, Docker и события fail2ban. Для RemnaWave доступен сбор метрик через `/metrics`.
- **Доступ и подписки.** Заявки на доступ, одноразовый тест, покупка и продление подписки, персональные ссылки подключения и напоминания об оплате.
- **Поддержка.** Тикеты с текстом, фотографиями и документами. Сотрудники могут брать обращения в работу, передавать коллегам, закрывать и архивировать их.
- **Техработы.** Немедленный или запланированный запуск, выбор серверов, продление и завершение работ с уведомлениями пользователей.
- **Администрирование.** Управление пользователями и сотрудниками, личные сообщения, рассылки всем пользователям или только администраторам, настройка реквизитов и цены, выгрузка клиентов в XLSX.

## Как устроена работа

### Для пользователя

Знакомство с ботом начинается с `/start` и заявки на доступ. После одобрения пользователь может обратиться в поддержку,
запросить тест или купить подписку. Персональная ссылка находится в разделе подписки; её можно открыть или добавить в Happ.
В профиле можно сохранить резервную электронную почту.

Оплаченная подписка также открывает просмотр состояния серверов. Бот напоминает о продлении за три дня, за день
и за 15 минут до окончания. Если оплата следующего периода не подтверждена, пользователь возвращается на базовый
уровень и получает уведомление с возможностью снова купить подписку или обратиться в поддержку.

### Для сотрудников

Администратор входит командой `/auth <пароль>`. Команда `/owner <пароль>` назначает единственного руководителя сервиса.
Остальные действия доступны через кнопки меню.

| Должность | Основные права |
| --- | --- |
| Специалист поддержки | Работа с пользователями, тикетами и заявками, выдача стандартного теста, отправка реквизитов |
| Инженер сопровождения | Дополнительно — управление техработами |
| Ведущий инженер сопровождения | Дополнительно — массовое изменение дат подписок и напоминания об оплате |
| Руководитель сервиса | Настройки оплаты, подтверждение платежей, произвольный срок теста и выгрузка клиентов |

Права сотрудника и пользовательская подписка учитываются отдельно. У руководителя — бессрочный оплаченный доступ.

## Подписки и оплата

Руководитель задаёт стандартную цену, реквизиты и даты платёжных периодов в разделе
«Администрирование → Настройки сервиса». По умолчанию тариф составляет 300 ₽ за три месяца.
Также предусмотрен безлимитный тестовый доступ без оплаты и даты окончания.

Покупка проходит в несколько шагов:

1. Пользователь создаёт заявку на подписку.
2. Администратор проверяет её и отправляет реквизиты.
3. Пользователь переводит деньги и нажимает «Я оплатил».
4. Руководитель подтверждает поступление, после чего бот активирует подписку до указанной даты.

Перед отправкой реквизитов в заявке можно нажать **«Цена и срок»** и назначить индивидуальные условия:

```text
500 | 2
500 | 2 | 31.12.2026 23:59
```

Первый вариант означает 500 ₽ за два календарных месяца от момента ввода. Второй задаёт точную дату окончания
в часовом поясе бота. Сумма указывается в целых рублях, срок — в месяцах. Бот покажет условия для подтверждения.
Они действуют только для этой заявки: следующее продление использует актуальную стандартную цену.
После отправки реквизитов условия заявки фиксируются.

В тексте реквизитов доступны подстановки `{amount}`, `{months}` и `{access_until}` — сумма, число месяцев и дата окончания.
Используйте их вместо записанных вручную цены и срока, чтобы сообщение соответствовало заявке.

Стандартный одноразовый тест выдаётся на 24 часа. Другой срок может выбрать руководитель.
Для теста сотрудник назначает новую ссылку с таким же сроком действия во внешней панели.
В карточке пользователя можно отдельно посмотреть сохранённую ссылку, заменить её или отправить пользователю.

MaintBot учитывает оплаты и сроки, но не проверяет банковские переводы автоматически и не создаёт доступ в RemnaWave.
Создание, продление и отключение доступа во внешней панели выполняются отдельно.

## Установка

Бот рассчитан на Linux и запуск через systemd. Версия Python для проекта указана в [.python-version](.python-version);
зависимости — в [app/requirements.txt](app/requirements.txt). Отдельная база данных не нужна: данные хранятся локально в JSON.
Подключение к Telegram работает через long polling, поэтому входящий порт или webhook не требуются.

Ниже используется каталог `/opt/maintbot`. Разместите в нём проект и выполните:

```bash
cd /opt/maintbot
python3.14 -m venv .venv
.venv/bin/python -m pip install -r app/requirements.txt

cp app/env.secrets.example app/env.secrets
chmod 600 app/env.secrets
mkdir -p data/conf/servers
cp examples/conf/bot.json data/conf/bot.json
cp examples/conf/servers/local-example.json data/conf/servers/local.json
```

### Токен и пароли

Заполните `app/env.secrets` по [примеру](app/env.secrets.example):

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Токен Telegram-бота, полученный у BotFather |
| `ADMIN_PASSWORD` | Пароль входа для администраторов |
| `OWNER_PASSWORD` | Отдельный пароль назначения руководителя |
| `REMNAWAVE_METRICS_USER`, `REMNAWAVE_METRICS_PASS` | Логин и пароль метрик, если endpoint использует HTTP Basic Auth |

Административные пароли должны отличаться и содержать не менее 16 символов. Обычным пользователям они не нужны.
Если метрики не требуют авторизации, оставьте обе переменные RemnaWave пустыми.

### Настройки бота

Основной конфиг — `data/conf/bot.json`. В нём задаются часовой пояс, пути, расписания уведомлений и параметры мониторинга.
За основу берите [готовый пример](examples/conf/bot.json): конфиг проверяется целиком, включая обязательные поля.

Для первого запуска обратите внимание на:

| Настройка | Что указать |
| --- | --- |
| `TZ` | Часовой пояс для дат подписок, уведомлений и техработ |
| `DATA_DIR` | Каталог данных; в примере `/opt/maintbot/data` |
| `PTB_PERSISTENCE_PATH` | Файл состояния диалогов; в примере `/opt/maintbot/data/telegram/persistence.pickle` |
| `INSTANCE_LOCK_PATH` | Для ручного запуска задайте `""`: блокировка будет храниться внутри `DATA_DIR/runtime` |

Если проект размещён в другом каталоге, измените пути соответственно.
Для нестандартного расположения конфигов используются `MAINTBOT_CONFIG_DIR` и `SECRETS_ENV_PATH`.

### Подключение серверов

Каждый файл в `data/conf/servers/` описывает один сервер. В скопированном примере замените адреса, домены и имена
контейнеров на свои; ненужные проверки уберите. Порядок серверов в меню задаётся полем `display_order`.
Изменения конфигурации серверов применяются после перезапуска бота.

- [Локальный сервер](examples/conf/servers/local-example.json) — проверки на хосте, где запущен бот.
- [Удалённый сервер](examples/conf/servers/remote-example.json) — подключение по SSH и пример источника метрик RemnaWave.

Для SSH укажите `connection.target`, настройте ключ в `SSH_IDENTITY_FILE` и файл доверенных хостов
в `SSH_KNOWN_HOSTS_FILE`. Для метрик RemnaWave задайте `REMNAWAVE_METRICS_URL` в конфиге бота,
а в конфиге сервера — `monitoring.source: "remnawave"` и UUID соответствующего узла.

Проверки UFW, Docker и fail2ban используют [maintbot-helper](deploy/maintbot-helper).
Он устанавливается на проверяемом хосте в `/usr/local/libexec/maintbot-helper` вместе с
[правилом sudo](deploy/maintbot-sudoers). Разрешённые контейнеры и пути к логам задаются в
`/etc/maintbot/docker-containers` и `/etc/maintbot/fail2ban-paths` по
[примеру контейнеров](deploy/docker-containers.example) и [примеру логов](deploy/fail2ban-paths.example).
Helper и эти файлы должны принадлежать root. Бот получает доступ к ограниченному набору операций чтения через helper;
членство в группе Docker для этого не требуется.

### Первый запуск

После заполнения конфигов создайте хранилище новой установки и запустите бот:

```bash
.venv/bin/python -m app.persistence.bootstrap --data-dir /opt/maintbot/data
.venv/bin/python -m app.config_check
.venv/bin/python -m app.launcher
```

Откройте личный чат с ботом, отправьте `/start`, затем `/owner <OWNER_PASSWORD>`.
В настройках сервиса задайте реквизиты, цену, даты периодов, контактную почту и текст помощи для пользователей.

### Постоянный запуск

В репозитории есть [готовый systemd unit](deploy/maintbot.service) для каталога `/opt/maintbot`
и пользователя `maintbot`. Создайте этого системного пользователя, предоставьте ему чтение кода и секретов,
а также запись в `data/`. Код, конфигурацию и helper оставьте под управлением root.
Если выбрали другие пути или имя пользователя, поправьте unit.

```bash
sudo cp deploy/maintbot.service /etc/systemd/system/maintbot.service
sudo systemctl daemon-reload
sudo systemctl enable --now maintbot.service
```

Для просмотра состояния и журнала:

```bash
systemctl status maintbot.service
journalctl -u maintbot.service -f
```

## Команды в Telegram

Основные действия доступны через кнопки. Команды позволяют сразу открыть нужный раздел:

| Команда | Действие |
| --- | --- |
| `/start`, `/menu` | Главное меню |
| `/help` | Помощь |
| `/subscription` | Подписка и персональная ссылка |
| `/ticket` | Обращение в поддержку |
| `/health` | Состояние серверов в пределах доступного уровня |
| `/users` | Управление пользователями для администратора |
| `/fail2ban` | События fail2ban для администратора |
| `/maint` | Техработы для сотрудников начиная с инженера сопровождения |
| `/auth <пароль>` | Вход администратора; также доступна команда `/login` |
| `/owner <пароль>` | Назначение руководителя сервиса |
| `/logout` | Выход из текущей сессии |
| `/cancel` | Отмена текущего диалога |
